# Development Guide

## Project Overview

A Python pygame Tetris game with an embedded Deep Q-Network (DQN) AI agent. UI labels are in French. Runs as a desktop app at 60 FPS with a finite state machine (FSM) driving navigation between menus, gameplay, AI training, and stats views.

## Architecture

### Data Flow

```
main.py → tetris.run() → TetrisApp.run()
                            │
                            └─ FSM loop (60 FPS):
                                 1. event.get() → state.handle_event(event) → Optional[State]
                                 2. state.update(dt, particles)            → Optional[State]
                                 3. state.draw(screen)
                                 4. display.flip() + particles.update()
```

Returning a new `State` from `handle_event`/`update` transitions the app; `None` stays. Concrete states are imported lazily inside methods to avoid import cycles (`tetris/states/base.py`).

### Layering (Domain → Presentation → Persistence)

| Layer | Packages | Responsibility |
|-------|----------|----------------|
| Domain | `tetris/game/` | Pure game logic: board, tetromino, scoring, stats, piece provider, rules |
| Presentation | `tetris/visuals/`, `tetris/audio/`, `tetris/states/` | Rendering, particle effects, SFX/music, FSM states |
| Persistence | `tetris/storage/` | JSON load/save for leaderboard, human stats |
| AI | `tetris/ai/`, `tetris/bots/` | DQN agent, El-Tetris bot, shared bot algorithms |
| External | `tetris/mcp_server.py` | FastMCP HTTP server for external agents |

### State Machine

```
MenuState (root, owns settings)
├── GameRulesMenuState
├── HumanMenuState → SeedEntryState, KeybindState, HumanStatsState
├── AIMenuState → TrainingMenuState, AIStatsState
├── BotMenuState
├── MCPMenuState
├── AudioMenuState
├── GameState (abstract base)
│   ├── HumanState
│   ├── AIState
│   ├── ElTetrisState
│   └── MCPState
├── LeaderboardState
└── Quit
```

`MenuState` is the settings owner: loads/saves `data/settings.json`. Child menu states hold a reference to `MenuState` and mutate its attributes directly, then trigger `save_settings()`.

## Code Conventions

### FSM States
- Subclass `State`, override `handle_event`, `update`, `draw`
- Transitions return a new `State` or `None`
- Import concrete states lazily inside methods (cycle avoidance)

### Keybinds
- `MenuState.keybinds` (dict: action → pygame keycode) → `HumanState._setup_keybinds()` builds the active `input_map`
- Modified by `KeybindState`

### Path Constants
- All data paths centralized in `tetris/settings.py` — never hardcode `"data/..."` in consumer modules
- `DATA_DIR = "data"`; callers create via `os.makedirs(DATA_DIR, exist_ok=True)`

### AI Exclusion from Human Stats
- `save_human_game()` only called in `GameOverState._handle_name_event()`
- `AIState` has its own `_on_episode_end()` and never creates `GameOverState` — architectural guarantee that AI games never pollute human stats

### Rendering
- `Renderer` is pure presentation — takes game state, draws to surface
- `ParticleSystem` handles physics-based effects
- Fonts are proportional (Arial) — use explicit pixel-positioned columns, not format-string alignment (`f"{x:<10}"` won't align)

### Music
- MIDI files in `media/` generated by `tetris/audio/midi_gen.py` (`ensure_midi_files()` at `AudioManager.__init__`)
- `AudioManager._parse_midi()` reads `.mid` files and synthesizes polyphonic audio via NumPy
- SFX are procedural NumPy synthesis (separate channel)

### Logging
- Use `from tetris.logger import get_logger` and `logger = get_logger(__name__)` at module level
- `logger.debug()` calls are no-ops when debug is OFF (level=WARNING); write to `data/debug.log` when debug is ON (level=DEBUG)
- `logger.error()` always writes
- Never use `print()` in game modules — only in CLI scripts (`verify_training.py`)

### Debug Mode
- Toggled via "Débogage" menu option (index 8 in `MenuState._OPTIONS`)
- When ON: `configure_logging(True)` sets DEBUG level; `GameState.debug=True` enables 7-bag visualization
- During gameplay, pressing **`d`** toggles visual debug overlay live (flips `GameState.debug` without changing logging level)

### Naming
- `PascalCase` classes, `snake_case` functions/variables, `UPPER_CASE` constants (in `settings.py`, `tetris/game/shapes.py`, `tetris/game/rules.py`)

## DQN AI Specifics

See `docs/ai.md` for the complete AI design document.

**Summary:**
- **Network**: `DQNetwork` — Input(17) → Dense(256, ReLU) → Dense(128, ReLU) → Output(1, Linear). V-function evaluates board quality per candidate placement.
- **State vector** (17-dim DT-20, normalized): `[lines_cleared, holes, aggregate_height, bumpiness, max_height, row_transitions, column_transitions, wells, hole_depth, rows_with_holes, *next_piece_one_hot(7)]`
- **Candidate generation**: soft-drop BFS with SRS wall kicks; enumerates all reachable placements including overhangs. Hold candidates enumerated when `_can_hold` is True. Look-ahead depth 1–3.
- **Move execution**: `_execute_move_sequence` replays BFS move sequence atomically (snaps to spawn before replay — fixes survival bug).
- **Target network sync**: Hard sync every 500 learn steps.
- **LR scheduling**: `ReduceLROnPlateau(mode="min", factor=0.5, patience=50, min_lr=1e-6)`
- **PER beta annealing**: 0.4 → 1.0 over 10,000 learn steps.
- **Curriculum**: Lives in `DQNAgent`, persisted in checkpoint. `advance_curriculum(max_level, freq)` advances level every `freq` episodes.
- **Seed reproducibility**: `_reset_episode` derives `_episode_seed = seed + episode` and re-seeds `random`, `np.random`, `torch.manual_seed`, and `PieceProvider`.
- **Modes**: `ai_mode="learning"` (epsilon-greedy + training, fast-forwards lock delay) vs `"playing"` (greedy, epsilon=0, no learning, full lock delay).
- **Observability** (5 tiers): Tier 1 = 26 new per-episode fields; Tier 2 = per-learn JSONL; Tier 3 = behavioral JSONL; Tier 4 = 9 reward components; Tier 5 = TensorBoard scalars.
- **Cooking-state indicator**: 4-signal health scoring (score trend, TD error trend, V-margin, epsilon) → "Trop cuit"/"Pas assez cuit"/"Bien cuit" + thermometer bar.
